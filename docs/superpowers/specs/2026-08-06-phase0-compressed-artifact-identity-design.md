# Phase 0 Compressed Artifact Identity Design

## Background

Phase 0 batch evidence currently records the output path and success state for each compressed artifact. The runner verifies that the target exists, is a regular file, and can be opened and closed. Review independently enumerates usable `.trimmed.jsonl` IDs and requires their set to match the successful results.

That proves artifact presence, but not artifact identity. Replacing a successful compressed file with different bytes under the same name after `phase0:run` leaves the set unchanged and can still satisfy the review gate.

## Goals

- Bind every newly successful compressed artifact to the exact bytes validated by `phase0:run`.
- Recompute compressed artifact SHA-256 values during `phase0:review` and reject same-name byte drift.
- Preserve the existing artifact-set gate independently from the new content-identity gate.
- Keep review output aggregate-only and free of digest values, paths, IDs, and compressed content.
- Keep older results v2 parseable while requiring a fresh batch before trust can lock when compressed digests are absent.

## Non-goals

- Do not parse compressed JSONL or validate its message semantics.
- Do not compare compressed messages with the source report or transcript.
- Do not change compression selection, output bytes, scorer, threshold, protected rules, candidate decisions, or public commands.
- Do not add signatures, keyed authentication, locking, or protection against an actor who can rewrite both results and artifacts.
- Do not reopen original transcripts during review.

## Approaches Considered

### Extend results v2 with a digest and a compatibility gate

Adopt this approach. Newly successful compress results include `output_sha256`. Review accepts an older otherwise-valid v2 result without that field but adds `compressed_integrity_unavailable`, keeping trust `review_required` until the batch is rerun. A present but malformed digest remains invalid evidence.

This closes the identity gap without a broad schema migration and distinguishes stale evidence from malformed evidence.

### Introduce `trimctx.phase0.results.v3`

A new schema version makes the required field explicit, but it expands migration handling, fixtures, documentation, and compatibility logic for an additive field in an unreleased development contract. It provides no stronger local integrity property than the selected approach.

### Hash only during review

Hashing only the current artifact provides no trusted baseline and cannot detect replacement. This does not satisfy the goal.

## Data Contract

For every successful compress result generated by `phase0:run`:

```json
{
  "compress": {
    "ok": true,
    "exit_code": 0,
    "output_file": "<private path>/<sample>.trimmed.jsonl",
    "output_sha256": "<lowercase 64-character SHA-256>"
  }
}
```

Failed compress results omit `output_sha256`. Review treats a missing digest on an otherwise-valid successful results v2 item as integrity evidence that is unavailable, not as malformed JSON. If the field is present, it must match `/^[a-f0-9]{64}$/`.

The privacy-narrowed review v2 validation object adds:

```json
{
  "expected_compressed_artifacts": 5,
  "matched_compressed_artifacts": 5,
  "matched_compressed_hashes": 5
}
```

No digest value is copied into review JSON or Markdown.

## Runner Data Flow

After a successful compress subprocess, the runner keeps the existing regular-file check and reads the artifact as a Buffer. A read failure converts the successful process result to `ok: false` with the existing privacy-safe artifact error. The SHA-256 is computed from that exact Buffer and stored only when validation succeeds.

The runner still skips artifact inspection when the compress subprocess itself fails. Empty regular files remain structurally readable and receive a digest; JSONL validity and compression semantics remain outside this gate.

## Review Data Flow

`loadReports()` changes the compressed collection from an ID set to an ID-to-SHA-256 map. It continues to select only regular `.trimmed.jsonl` entries, reads each usable file without parsing it, and hashes the exact bytes read. Unreadable artifacts are omitted from the map and therefore continue to fail the set gate.

`loadPhase0ValidationEvidence()` derives:

- the expected ID set from successful compress results;
- the expected digest map from successful results that contain valid digests;
- the actual ID set from the keys of the recomputed digest map;
- `matched_compressed_artifacts` from matching IDs;
- `matched_compressed_hashes` from matching ID and digest pairs.

The existing `compressed_set_mismatch` remains responsible for missing or extra usable files. `compressed_integrity_unavailable` is added when any successful result lacks a digest. `compressed_hash_mismatch` is added only when an expected and actual artifact share an ID but their digests differ.

## Compatibility And Error Boundaries

- Results v1 behavior remains `report_integrity_unavailable`.
- Older valid results v2 without compressed digests remain structurally available but cannot become ready or locked.
- A malformed present digest produces `invalid_phase0_results` without echoing its value.
- A missing actual file produces `compressed_set_mismatch`; it is not also mislabeled as a hash mismatch.
- A same-name changed file produces `compressed_hash_mismatch` while the set remains matched.
- Review issue ordering remains deterministic.

## Privacy And Security Boundary

`phase0-results.json` remains private and contains output paths plus exact artifact digests. Review JSON and Markdown expose only matched/expected counts and fixed issue codes. They never include compressed bytes, paths, IDs, digest values, parser errors, or operating-system errors.

SHA-256 detects accidental or unilateral artifact drift. It is not a signature and does not protect against a party able to rewrite both the result evidence and the artifact.

## Test Strategy

- Runner regression: successful compression records the SHA-256 of the exact bytes written.
- Evidence regression: replacing one actual digest under the same ID yields five matched artifacts, four matched hashes, and only `compressed_hash_mismatch`.
- Compatibility regression: a successful v2 result missing `output_sha256` yields `compressed_integrity_unavailable` rather than `invalid_phase0_results`.
- Validation regression: a malformed present digest yields `invalid_phase0_results` without leaking the value.
- End-to-end review regression: overwrite one fixture `.trimmed.jsonl` after results generation and confirm trust remains `review_required`, the Markdown aggregate is 4/5, and no private sentinel or digest appears.
- Run focused Phase 0 tests, the full suite, build, package-content smoke, npm dry-run inspection, strict script type-checking, and `git diff --check`.

## Success Criteria

- Every newly successful compress result records the exact artifact SHA-256.
- Same-name compressed byte drift cannot satisfy Phase 0 readiness.
- Missing legacy compressed integrity evidence cannot lock trust and is classified precisely.
- Artifact-set and artifact-hash counts remain independently auditable.
- No compressed content or identifying value enters review output.
- Compression behavior, Report v2, six-command CLI behavior, and original transcript immutability remain unchanged.
