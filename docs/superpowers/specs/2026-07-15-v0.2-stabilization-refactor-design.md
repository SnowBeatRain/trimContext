# trimctx v0.2 稳定化与渐进重构设计

## 目标

在不重新评估真实样本有效性、不改变评分/压缩行为的前提下，修复 Windows 发布 smoke，统一集成副作用文档，并把 `src/cli.ts` 中已经稳定的职责迁移到可独立测试的模块。

## 范围

本轮包含：

- 修复 Windows 全局 npm prefix 下 package root 的测试定位。
- 明确 SessionStart hook 写 `CLAUDE_ENV_FILE`，Stop hook 写项目 `.claude/CLAUDE.md` 的实际副作用。
- 保留 `current --compress` 行为，但从推荐路径中降级为 advanced/legacy 用法。
- 抽取文件同路径保护、CLI 分析参数解析、分析 pipeline、session discovery。
- 将核心分析命令、new-chat 命令和客户端集成命令从 `src/cli.ts` 拆出。

本轮不包含：

- Phase 0 或真实样本重新验证。
- scorer、threshold、safety、report schema 或 compression decision 调整。
- 新命令、新参数、Web UI、MCP、LLM 或数据库。
- 删除 `handoff` 或 `current --compress` 等兼容入口。

## 架构

`src/cli.ts` 只负责创建 Commander 根程序、读取版本、注册命令和统一错误出口。命令行为分别放入 `src/commands/analysis.ts`、`src/commands/new-chat.ts` 和 `src/commands/integrations.ts`。

共享能力下沉到：

- `src/commands/shared/analysis-options.ts`：CLI 参数解析和显式输入路径解析。
- `src/platform/files.ts`：同文件判断、输出路径保护和存在性检查。
- `src/core/pipeline.ts`：读取输入并执行 parser -> safety/scorer -> report。
- `src/sessions/discovery.ts`：Claude/Codex session 查找和用户提示。

`src/core/session.ts` 暂时保留 re-export facade，避免内部导入一次性迁移造成不必要兼容风险。

## 行为边界

- `trimctx --help`、`--version` 和所有已有子命令保持不变。
- 默认摘要、JSON report、handoff package 和 init 输出保持不变。
- `compress` 仍只删除非 protected 的 `remove_candidate`。
- hooks 的运行行为本轮不改，只修正文档披露。
- 所有输出路径继续拒绝覆盖输入文件。

## 测试策略

- 使用当前失败的 packed-install smoke 作为 Windows 修复的 RED。
- 为新的分析参数和文件安全模块先添加直接单元测试。
- pipeline/session/command 拆分依赖现有 CLI、hook、compressor 和 package tests 做行为回归。
- 每阶段运行针对性测试，最后运行 `npm test`、`npm run build`、`git diff --check` 和 `npm pack --dry-run --json`。
