# trimctx v0.3 可用性设计

## 背景

trimctx 0.2 已具备本地 JSONL 解析、上下文健康分析、报告、压缩副本、当前会话发现、handoff 产物和 Claude/Codex 客户端资产安装能力。但当前体验仍偏工程工具：用户需要理解 JSONL 路径、source 类型、rot score、Phase 0、candidate 等概念，首次使用成本高，产品价值不够直接。

v0.3 的目标不是增强压缩算法，而是把现有能力包装成用户能立刻使用的“长对话续接助手”。

## 产品目标

把 trimctx 从：

> 分析 JSONL 的 CLI 工具

调整为：

> 一键判断长对话是否该续接，并生成下一窗口可用上下文包的助手

成功标准：

- 用户无需手动提供 JSONL 路径即可完成一次有价值的检查。
- 默认输出能在一屏内说明状态、原因和下一步。
- `/trimctx` 与裸 `trimctx` 的默认心智一致：检查当前/最近会话并给建议。
- `handoff` 成为主路径，`compress` 保持高级命令。
- 不修改原始 transcript，不引入 LLM 调用，不降低 Phase 0 安全边界。

## 非目标

- 不做 Web UI。
- 不做 MCP。
- 不新增 LLM 总结能力。
- 不改变核心安全规则和评分算法。
- 不让 `compress_candidate` 自动影响压缩输出。
- 不自动修改或替换正在运行的 AI 客户端上下文。

## 用户路径

### 路径 1：新用户终端首次使用

```bash
npm install -g trimctx
trimctx init
trimctx
```

预期体验：

1. `trimctx init` 安装客户端资产后，明确提示下一步可运行的命令。
2. `trimctx` 自动查找当前或最近 Claude/Codex 会话。
3. 输出当前会话状态、主要原因和建议下一步。

### 路径 2：Claude Code 当前窗口使用

```text
/trimctx
```

预期体验：

1. 如果 hook 已绑定当前 transcript，优先分析当前窗口。
2. 如果 hook 未绑定，提示重启 Claude Code 或运行安装 hooks 的命令。
3. 不要求用户复制 JSONL 路径。

### 路径 3：准备开新窗口续接

```bash
trimctx handoff
```

预期体验：

1. 自动发现当前/最近会话。
2. 生成 `.trimctx/handoffs/<id>/` 包。
3. 告诉用户复制 `next-context.md` 到新窗口。
4. 明确说明原始会话未被修改。

## CLI 行为设计

### 裸命令 `trimctx`

新增默认动作：不带子命令时执行“当前会话健康检查”。

解析顺序：

1. 若 `TRIMCTX_TRANSCRIPT_PATH` 存在且可读，分析该文件。
2. 否则扫描最近 Claude/Codex 会话，等价于 `trimctx current --source auto`。
3. 若找不到会话，输出人话错误和下一步建议。

默认输出使用用户摘要，不输出完整 JSON。

保留现有子命令：

- `trimctx analyze <file>`：高级/显式文件路径。
- `trimctx current`：显式当前会话发现。
- `trimctx report`：完整 JSON 报告。
- `trimctx compress`：高级安全压缩副本。
- `trimctx handoff`：主续接路径。

### `trimctx handoff` 无参数

当前已有 `[file]` 可选参数，但解析依赖 `resolveInputFile(file)`。v0.3 应确保无参数时按与裸命令一致的顺序自动发现会话：

1. `TRIMCTX_TRANSCRIPT_PATH`
2. 最近 Claude/Codex 会话
3. 找不到则输出修复建议

默认输出目录保持：

```text
.trimctx/handoffs/<id>/
```

新增或确认包含：

```text
handoff.md
next-context.md
report.json
README.md
```

`README.md` 面向用户解释：

- 这个包是什么。
- 下一窗口应该复制哪个文件。
- 原始 transcript 没有被修改。
- 需要审计时查看 `report.json`。

### `trimctx init` 成功提示

安装结束时追加“下一步”区域：

```text
安装好了。

现在你可以这样用：

Claude Code 当前窗口：
  /trimctx

终端里：
  trimctx
  trimctx handoff

如果 /trimctx 找不到当前会话，请重启 Claude Code。
```

如果 `--dry-run`，只展示将安装内容，不展示“安装好了”。

## 默认摘要设计

默认摘要应避免工程术语优先，采用产品化结构：

```text
trimctx 看了一下当前会话：

状态：建议开新窗口续接
原因：
- 当前会话约 218K tokens，已经偏重
- 旧工具输出和过期讨论较多
- 最近关键上下文仍完整

下一步：
  trimctx handoff
  然后把 .trimctx/handoffs/<id>/next-context.md 贴到新窗口

高级审计：
  trimctx report <file> -o report.json
```

状态文案建议分三档：

1. `可以继续当前会话`：上下文压力低，风险低。
2. `建议准备 handoff`：上下文压力中等，已有明显低价值内容。
3. `建议开新窗口续接`：上下文压力高，handoff 价值明显。

内部指标仍可用于判断，但默认文案不优先展示 `rot score`、`Phase 0`、`remove_candidate` 等术语。必要安全说明以人话呈现：

- “trimctx 只做本地分析，没有上传文件。”
- “压缩输出需要先看报告，默认建议先用 handoff。”

## 组件与实现边界

### 新增/调整模块

- `src/cli/default-action.ts` 或同等小模块：封装裸命令默认动作。
- `src/cli/user-summary.ts` 或扩展 `format-summary.ts`：生成产品化摘要。
- `src/core/session.ts`：复用并补齐“env 当前 transcript 优先”的发现逻辑。
- `src/core/handoff.ts`：补齐 handoff package README 生成。

### 保持不变

- parser、safety、scorer、reporter 核心管线不做行为变化。
- `compressFile` 不改变原始文件的安全约束。
- JSON report schema 不因默认摘要变化而破坏兼容。

## 错误处理

找不到会话时输出：

```text
没找到可分析的 Claude/Codex 会话。

你可以：
1. 在 Claude Code 里重启窗口后运行 /trimctx
2. 或显式指定文件：trimctx analyze path/to/session.jsonl
3. 或安装/刷新客户端资产：trimctx init
```

文件不可读时输出路径和修复建议，不显示不必要的 stack trace。调试信息可由未来 `--debug` 承载，本轮不新增。

- 裸 `trimctx` 在 env transcript 存在时分析该文件。
- 裸 `trimctx` 在 env 不存在时回退到 current discovery，或在测试中 mock discovery。
- `trimctx handoff` 无参数可使用 env transcript 生成 package。
- handoff package 包含 `README.md`，且内容指向 `next-context.md`。
- `trimctx init --dry-run` 不输出“安装好了”。
- `trimctx init` 正常输出下一步指引。

## 风险与缓解

### 风险：裸命令行为影响 `--help` 心智

缓解：保留 `trimctx --help` 原行为；只有无参数时执行默认动作。

### 风险：自动发现误选最近会话

缓解：优先使用 hook env；摘要中显示被分析文件的 home-relative 路径；用户可用 `analyze <file>` 显式覆盖。

### 风险：过度承诺“压缩安全”

缓解：默认 CTA 是 handoff，不是 compress；压缩仍标注为审计后高级命令。

### 风险：摘要隐藏太多调试信息

缓解：完整信息仍通过 `report` 和 `analyze --json` 提供。

## 验收标准

- 不带子命令运行 `trimctx` 能给出有用结果或清晰修复建议。
- `trimctx handoff` 无参数能生成可直接用于下一窗口的 handoff package。
- 默认输出一屏内能回答：状态是什么、为什么、下一步做什么。
- 安装完成后的提示能让新用户马上知道 `/trimctx`、`trimctx`、`trimctx handoff`。
- `npm test` 和 `npm run build` 通过。
